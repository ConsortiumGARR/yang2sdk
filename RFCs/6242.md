# RFC 6242: Using the NETCONF Protocol over Secure Shell (SSH)

> Normalized agent-facing summary. Source: RFC 6242 (obsoletes RFC 4742), Standards Track, June 2011.
> Author: M. Wasserman (Painless Security).
> Full text: https://www.rfc-editor.org/info/rfc6242

## 1. Stack and session setup (§3)

- Stack: NETCONF [RFC 6241] over SSH connection [RFC 4254] over SSH transport [RFC 4253].
- Default TCP port **830** (IANA); alternative ports MUST be configurable.
- Sequence: TCP/830 → SSH key exchange → `ssh-userauth` [RFC 4252] (username is passed to NETCONF; session is dropped if the username is not valid XML) → open `session` channel → invoke subsystem **`netconf`** (SSHv2 only).
- Capabilities exchange: immediate, simultaneous `<hello>` documents (with capabilities + session-id) right after subsystem start.

## 2. Framing (§4) — the load-bearing detail

- If **both** peers advertise `:base:1.1` → **chunked framing**: `LF '#' chunk-size LF chunk-data` … `LF '#' '#' LF` terminator. `chunk-size` is decimal, no leading zeros, max 4294967295. Invalid size / decode error → terminate the SSH channel immediately (buffer-overrun protection).
- Otherwise (`:base:1.0` only) → legacy end-of-message marker `]]>]]>`, which is vulnerable to payload injection if the delimiter appears inside XML attributes/comments. Chunked framing (new vs RFC 4742) removes this vector.

## 3. Session teardown (§5)

Client sends `<close-session>` → server replies `<rpc-reply><ok/></rpc-reply>` → server closes the SSH channel immediately (later mutations ignored).

## 4. Security posture (§6–§7)

- Mutual identity verification MUST precede any data/credential transfer; strong transport encryption is required (configs/keys are sensitive).
- Distinct default port 830 aids firewall filtering but advertises attack surface.
- Strict XML validity check on the authenticated username (new vs RFC 4742); standardized SSH-vs-NETCONF role/entity naming; errata integrated.

## 5. yang2sdk relevance

- `ncclient` handles this layer; the template's `hostkey_verify` default (`True`, opt-out only with warning) is the direct application of §6. Never silently disable host-key verification.
- Chunked vs EOM framing explains why `:base:1.1` capability advertisement matters during `<hello>`; do not pin framing assumptions in generated code.
