# RFC 8341: Network Configuration Access Control Model (NACM)

> Normalized agent-facing summary. Source: RFC 8341 (obsoletes RFC 6536), IETF STD 91, March 2018.
> Authors: A. Bierman (YumaWorks), M. Bjorklund (Tail-f Systems).
> ⚠️ This RFC is the **access-control model**, not the RESTCONF protocol (that is RFC 8040). A previous repo map mislabeled it; this file corrects that.
> Full text: https://www.rfc-editor.org/info/rfc8341

Covers the operations + content layers of NETCONF [RFC 6241] and RESTCONF [RFC 8040]; YANG 1.1 [RFC 7950] compatible (actions, nested notifications).

## 1. Control points (§2–§3)

1. **Protocol operation** — authorize RPC/action execution.
2. **Datastore** — authorize CRUD on data nodes in conventional + operational datastores.
3. **Notification** — authorize receipt of specific event streams/types.

Model: users ⊂ groups (incl. RADIUS/transport-asserted external groups). YANG extensions `default-deny-write` / `default-deny-all` tag sensitive nodes machine-readably.

## 2. Knobs (`ietf-netconf-acm` module, §8)

`enable-nacm` (default true), `read-default` (permit), `write-default` (**deny**), `exec-default` (permit), `enable-external-groups` (true). A `recovery_session` bypasses all checks (implementation-specific emergency rescue). Counters: `denied-operations`, `denied-data-writes`, `denied-notifications`.

CRUDX: create / read / update / delete / exec. RESTCONF mapping: `GET/HEAD`→read, `POST(data)`→create, `POST(action)`→exec, `PUT`→create+update, `PATCH`→update, `DELETE`→delete.

## 3. Enforcement order (§3)

- **Incoming RPC:** bypass if NACM off / recovery session / `<close-session>`. Else resolve groups → walk matching `rule-list`s (user-ordered) → walk `rule`s: match `(module, rpc-name, access-operations)` → permit/deny. Unmatched: deny if `default-deny-all` tagged; `<kill-session>` / `<delete-config>` always denied; else `exec-default`.
- **Data node:** same walk with `(module, path, access-operations)`. Unmatched: deny read on `default-deny-all`, deny write on `default-deny-write|all`; else `read-default` / `write-default` / `exec-default`. Server-side implicit changes (`when`, `choice` evaluation) need no rights.
- **Outgoing notification:** nested → read-access check on ancestor hierarchy + node; top-level → `notification`-type rules with `read`. Unmatched `default-deny-all` → drop; else `read-default`.

## 4. `ietf-netconf-acm` schema sketch (§8)

`nacm/{enable-nacm, read-default, write-default, exec-default, enable-external-groups, groups/group[key name]{user-name*}, rule-list[key name, ordered-by user]{group*, rule[key name]{module-name, rule-type choice(protocol-operation{rpc-name} | notification{notification-name} | data-node{path}), access-operations, action, comment}}}`.

## 5. yang2sdk relevance

- Explains **server-side** `access-denied` / denied-write counters: a generated-client `update()` can be schema-valid yet rejected by NACM. Map such failures to authorization, not to model bugs.
- `write-default=deny` is why least-privilege automation accounts need explicit rules; document required NACM rules alongside generated clients, never credentials.
