# RFC 8527: RESTCONF Extensions to Support NMDA

> Normalized agent-facing summary. Source: RFC 8527 (updates RFC 8040), Standards Track, March 2019.
> Authors: M. Bjorklund, J. Schoenwaelder, P. Shafer, K. Watsen, R. Wilton.
> Full text: https://www.rfc-editor.org/info/rfc8527

Extends RESTCONF [RFC 8040] for the NMDA datastore architecture [RFC 8342]. Fully backwards compatible: only new resources/params, existing semantics unchanged (§1).

## 1. Requirements (§2)

NMDA-compliant server MUST support the `operational` datastore and `ietf-yang-library` (RFC 8525, ≥2019-01-04). Clients probe NMDA support via `HEAD`/`GET {+restconf}/ds/ietf-datastores:operational`; datastore/module inventory comes from yang-library in the operational datastore.

## 2. New datastore resources (§3.1)

Template `{+restconf}/ds/<datastore>`, where `<datastore>` is a namespace-qualified `identityref` (RFC 7951 §6.8 rules, qualified form mandatory) derived from `ietf-datastores:datastore`:

- `{+restconf}/ds/ietf-datastores:operational` (MUST implement), `…:running`, `…:intended`, plus server-defined (e.g. `example-ds-ephemeral:ds-ephemeral`).
- YANG **actions** are invocable only under the operational resource.
- Same protocol ops as `{+restconf}/data` except: dynamic datastores excluded, read-only datastores reject writes with `405` / `operation-not-supported`, RFC 8040 §3.5.4¶3 does not apply under `/ds/`.

## 3. Operation deltas (§3.2)

- `with-defaults` on the operational datastore is OPTIONAL (capability `…:with-operational-defaults:1.0`): unset/`explicit`/`report-all`/`report-all-tagged` → "in use" values; `trim` → drop schema-default matches (§3.2.1).
- New `with-origin` query param (capability `…:with-origin:1.0`): include `or:origin` annotations; valid only on operational-derived datastores, else `400` / `invalid-value` (§3.2.2). Child annotations may be omitted when equal to the parent's (per `ietf-origin`).

## 4. yang2sdk relevance

- Current generated RESTCONF clients target the pre-NMDA `{+restconf}/data` + `{+restconf}/operations` surface (RFC 8040). Any move to `/ds/` addressing, `with-origin`, or NMDA content semantics must follow this RFC — not ad-hoc URL invention. Security posture inherits RFC 8040 §12 via NACM [RFC 8341] (§5).
