# RFC 7951: JSON Encoding of Data Modeled with YANG

> Normalized agent-facing summary. Source: RFC 7951, Standards Track, August 2016. Author: L. Lhotka (CZ.NIC).
> Full text: https://www.rfc-editor.org/info/rfc7951

Encoding rules for config data, state data, RPC/action parameters, and notifications as JSON text. Top-level structure is always an object (§3); member order is never significant; duplicate member names forbidden (I-JSON profile, §7).

## 1. Names and namespaces (§4) — load-bearing for yang2sdk

Member name ABNF: `member-name = [identifier ":"] identifier`.

- **Namespace-qualified** (`module:node`) MUST be used for all members of a top-level object, and whenever a node lives in a different module than its parent (e.g. augmentations).
- **Simple** form otherwise.
- Same qualified form is used inside `identityref` / `instance-identifier` values (§§6.8, 6.11).

This is why generated RESTCONF models use `Field(alias="module:leaf")`.

## 2. Data-node encoding (§5)

- `leaf` → name/value (§5.1); `container`/`anydata` → name/object (§§5.2, 5.5); `leaf-list` → name/array of scalars (§5.3, `ordered-by` honored); `list` → name/array of objects (§5.4, key-first ordering NOT required unlike XML); `anyxml` → name/value, I-JSON constrained (§5.6). `@`-prefixed members are reserved for metadata (§5.7, e.g. RFC 7952).

## 3. Type mapping (§6) — what the IR implements

| YANG type | JSON form (§) |
|---|---|
| `int8/16/32`, `uint8/16/32` | JSON number (§6.1) |
| **`int64`, `uint64`, `decimal64`** | **JSON string** with the §9 lexical form (§6.1; I-JSON safe). yang2sdk `Int64`/`Uint64`/`Decimal64` serializers implement this. |
| `string` | JSON string (§6.2) |
| `boolean` | `true`/`false` (§6.3) |
| `enumeration` | string, the `enum` name (§6.4) |
| `bits` | string, space-separated set bit names (§6.5) |
| `binary` | string, base64 (§6.6; the one I-JSON deviation) |
| `leafref` | encoded as the referenced type (§6.7; resolve-then-encode) |
| `identityref` | string, qualified form when cross-module (§6.8) |
| `empty` | single-element array `[null]` (§6.9; never bare `null`) |
| `union` | value of a member type; JSON typing disambiguates (number vs string) (§6.10) |
| `instance-identifier` | string; top-level node always qualified (§6.11) |

## 4. Rules for agents

- Never emit 64-bit integers as JSON numbers.
- `empty` is `[null]` on the wire; `bits` order follows bit positions.
- Union validation MUST consider JSON type information, not just lexical form.
