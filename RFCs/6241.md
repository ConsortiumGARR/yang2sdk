# RFC 6241: Network Configuration Protocol (NETCONF)

> Normalized agent-facing summary. Source: RFC 6241 (obsoletes RFC 4741), Standards Track, June 2011.
> Eds: R. Enns, M. Bjorklund, J. Schoenwaelder, A. Bierman.
> YANG archives: Appendix B (schema), Appendix C (`ietf-netconf` module, namespace `urn:ietf:params:xml:ns:netconf:base:1.0`).
> Full text: https://www.rfc-editor.org/info/rfc6241

## 1. Layered architecture (§1)

| Layer | Content |
|---|---|
| L4 Content | Config + state data. Out of RFC scope; modeled via YANG (RFC 7950). |
| L3 Operations | RPC-based execution (`<edit-config>`, `<get>`, …). |
| L2 Messages | Framing (`<rpc>`, `<rpc-reply>`, `<notification>` per RFC 5717). |
| L1 Transport | Persistent, connection-oriented, reliable, sequenced. MUST provide peer auth, integrity, confidentiality, replay protection. Mandatory: SSH (RFC 6242). Optional: TLS (RFC 5246), BEEP. Yields a "NETCONF username" used for authorization. |

Session init: simultaneous `<hello>` exchange on connect. Each peer lists capabilities; base URN `urn:ietf:params:netconf:base:1.1`. Highest common version wins; mismatch → terminate. Server MUST send `<session-id>`; client MUST NOT (violation → terminate).

## 2. RPC message layer (§2)

- Encoding: well-formed XML, UTF-8. No DTDs.
- Pipelining: server MUST process serially, replying in request-arrival order.
- `<rpc message-id="STR">`: mandatory unique ID, echoed back unmodified in `<rpc-reply>`.
- `<ok/>`: empty success marker.
- `<rpc-error>` (multiple allowed): `error-type` (transport | rpc | protocol | application), `error-tag` (standard token, see §7), `error-severity` (error | warning), optional `error-app-tag`, `error-path` (XPath to offending node), `error-message` (human-readable, `xml:lang` allowed), `error-info` (protocol/model-specific detail).

## 3. Datastore model (§3–§4 of RFC text; §§4–5 here map to datastores/filtering)

- Datastore = full config dataset needed to take a device from default to operational.
- Configuration data (writable) ≠ state data (read-only stats/runtime).
- `<running/>`: active config. Mandatory, always present. `<candidate/>`, `<startup/>`: capability-gated.
- `<get-config>` → config data only. `<get>` → config + state.
- yang2sdk relevance: NETCONF `retrieve(source=...)` defaults to `running` for `content="config"`, `operational` otherwise; legacy fallback uses `get-config` vs `get` on exactly this rule.

## 4. Subtree filtering (§6)

`<filter type="subtree">` inside `<get>` / `<get-config>`:

1. **Namespace selection:** match on namespace URI (unqualified/prefix-free `xmlns=""` acts as wildcard).
2. **Attribute match:** node selected iff all stated XML attributes match.
3. **Containment nodes:** structural branch nodes used to walk the hierarchy.
4. **Selection nodes:** empty leaf (e.g. `<users/>`) returns exactly that subtree.
5. **Content match nodes:** leaf with a text value; siblings AND-ed. Match → returns the node + siblings + ancestor keys; no match → sibling set pruned.
6. **Errata 3980:** key / instance-identifier leaves of processed siblings MAY always be returned to keep structural integrity.

yang2sdk relevance: `build_filter_tree()` in the NETCONF `_base` template implements namespace + key-leaf selection per these rules.

## 5. Protocol operations (§7)

- `<get-config>` (`<source>`, `<filter>`), `<get>` (`<filter>`).
- `<edit-config>` (`<target>`, `<default-operation>`, `<test-option>`, `<error-option>`, `<config>` | `<url>`). `operation` attribute values (NETCONF namespace, unqualified): `merge` (default), `replace` (replace-or-create), `create` (`data-exists` if present), `delete` (`data-missing` if absent), `remove` (delete-or-ignore).
- `<copy-config>` (`<target>`, `<source>`, inline `<config>` allowed), `<delete-config>` (`<target>` = startup | url; `<running/>` cannot be deleted).
- `<lock>` (global; fails with `lock-denied` + holder `<session-id>`; reverts on close) / `<unlock>` (same session only).
- `<close-session>` (graceful, releases locks) / `<kill-session>` (`<session-id>`, forceful).

## 6. Standard capabilities (§8)

URN form `urn:ietf:params:netconf:capability:{name}:1.x` (shorthand `:{name}`):

1. `:writable-running` (1.0) — direct `<running/>` writes in `edit-config` / `copy-config`.
2. `:candidate` (1.0) — `<candidate/>` workspace + `<commit>` (atomic candidate→running) + `<discard-changes>`. Uncommitted changes die on lock release / session failure.
3. `:confirmed-commit:1.1` (1.1, requires `:candidate`) — `<commit>` gains `<confirmed/>`, `<confirm-timeout>` (default 600 s), `<persist>` / `<persist-id>` tokens; adds `<cancel-commit>`. Errata EID 5790: revert on pre-timeout session loss unless persisted; reboot restores pre-commit state unless persisted; `<kill-session>` mid-commit restores prior state.
4. `:rollback-on-error` (1.0) — `<error-option>rollback-on-error` aborts + reverts the transaction on any `error`-severity failure.
5. `:validate:1.1` (1.1) — `<validate>` op on `<source>`; `<test-option>` (`test-then-set` default | `set` | `test-only`) on `edit-config`.
6. `:startup` (1.0) — separate `<startup/>` datastore, explicit `<copy-config>` to persist; valid source/target for `get-config`, `copy-config`, `lock`, `unlock`, `validate`, `delete-config`.
7. `:url` (1.0) — URL instead of inline config (`scheme=http,ftp,file,…`); extends `edit-config`, `copy-config`, `delete-config`, `validate`.
8. `:xpath` (1.0) — `type="xpath" select="EXPR"` filters in `get` / `get-config`, evaluated at root with filter's namespace scope.

yang2sdk relevance: `NetconfClient` capability discovery (`has_candidate`, `has_writable_running`, `has_nmda`) and default-write-target selection implement this section directly.

## 7. Standard error tags (Appendix A)

`in-use` | `invalid-value` | `too-big` | `missing-attribute` | `bad-attribute` |
`unknown-attribute` | `missing-element` | `bad-element` | `unknown-element` |
`unknown-namespace` | `access-denied` | `lock-denied` | `resource-denied` |
`rollback-failed` | `data-exists` | `data-missing` | `operation-not-supported` |
`operation-failed` | `malformed-message` (new in 1.1) | `partial-operation` (obsolete)
